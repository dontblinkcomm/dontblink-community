BNB Chain · four.meme

z500 Launch API

用一次 HTTP 调用发一枚 four.meme 代币。和 pump.fun 的接口一样是 你调用、你付钱、币归你 —— 不同的是发出来的每一枚币自带一个 谁都取不走的金库,包括我们。

BASE https://z500-api.nyxance.com

一次发射

四步,其中一步不用你做。我们不托管任何东西 —— 每次发射生成一个一次性钱包,你往它打钱,币和金库的所有权直接落到你指定的地址。

  1. 01

    建单

    POST /launch → 拿到一个专属钱包地址和确切金额

  2. 02

    打钱

    往那个地址转 BNB,一笔普通转账。批量的关键在这一步 —— 建 N 单拿 N 个地址,一笔 multisend 打完

  3. —

    发射(自动)

    钱到了就发,不用再调任何接口。上游抽风会自动重试

  4. 03

    查

    GET /launch/:id → 币地址、金库地址、交易哈希

最短的一次

# 建单
curl -X POST https://z500-api.nyxance.com/launch \
  -H 'authorization: Bearer <你的 key>' \
  -H 'content-type: application/json' \
  -H 'idempotency-key: batch-01' \
  -d '{
    "creator": "0xYourAddress",
    "networkToken": "0x7b630F080807DF83908b4aDE46BA6396EE66b098",
    "request": {
      "name": "My Coin",
      "shortName": "MYC",
      "desc": "…",
      "imageUrl": "https://example.com/logo.png",
      "presaleQuoteBnb": "0.01"
    }
  }'

# → {"id":42,"launchWallet":"0x…","requiredBnb":"0.016","replayed":false}
# 往 launchWallet 转 0.016 BNB,然后:

curl https://z500-api.nyxance.com/launch/42
POST/launch 需要 key

建一单发射,返回要打钱的钱包地址。

发币字段必须嵌在 request 里。 平铺在顶层是最常见的一个错,而且它曾经是静默的 —— 我们的第一个真实用户把税率写在顶层,六个数字被丢掉,链上跑出来是默认值,他以为生效了。现在这种形状会直接返回 bad_envelope。

字段类型说明
creatoraddress币和金库最终归谁。不是我们,也不是那个一次性钱包
networkTokenaddress发进哪个社区,见 /communities
request.namestring币名
request.shortNamestring符号
request.descstring最长 400 字,four.meme 的硬上限
request.imageUrlurl或 imageBase64 + imageMime。必须公网可达
request.presaleQuoteBnbstring不是手续费 —— 它换成你自己的币,成为持有人空投储备
request.callbackUrlurl选填,终态时我们 POST 给它。见回调
request.presetstringindex(默认)或 volume。见税率

返回体里的 requiredBnb = 你的 presaleQuoteBnb + 0.006 BNB gas 余量。多打的会退回给 creator,不会留在我们这。

GET/launch/:id公开

查一单的状态。读接口一律不需要 key —— 这个平台的主张是每个数字都能自己核,把数据藏起来是自相矛盾。

{
  "id": 42,
  "status": "launched",
  "token": "0x…",        // 你的币
  "clone": "0x…",        // 它的金库,owner 是你
  "createTx": "0x…",
  "reserve": "1722034412733150733986543",
  "claimsEpoch": 0,
  "errorCode": null   // 失败时才有,见错误码
}
status意思
awaiting_funds等你往 launchWallet 打钱
launching钱到了,正在发
launched发出来了,token 和 clone 有值
published毕业,持有人空投已发
failed失败,带 error 和 errorCode
expired资金窗口内一直没打钱。钱包是空的,没有东西被扣住
POST/launch/:id/retry需要 key

把一单 failed 放回队列。钱已经在落地钱包里的话马上就会跑。

为什么这个接口必须存在: 失败的单里躺着你的钱。在有它之前,一单因为 four.meme 连不上而失败之后就一直是 failed,直到有人注意到并去服务器上手动跑一次 —— 我们的第一个真实客户就这么等了几天,而失败原因只是上游当时连不上。

现在这类失败会自动重捞(最多 5 次,退避 1/5/15/30/60 分钟),而你也不必等我们发现。自动和手动共用同一个上限。

GET/launches公开

按 ?creator=、?community= 或 ?status= 筛。

?status=failed 是给没填回调的人主动发现失败用的。回调是推,这是拉,建议两条都用 —— 只靠推的话,回调地址填错的那一刻起就再也不会有人知道出了事。

GET/communities公开

能发币进去的社区,以及每个社区对分成的上下限。

{
  "networkToken": "0x7b630F080807DF83908b4aDE46BA6396EE66b098",
  "name": "dontblink",
  "minBurnBps": 3000,      // 你的 burnBps 不能低于这个
  "maxCreatorBps": 1000,    // 你的 creatorBps 不能高于这个
  "maxSubHolderBps": 0,
  "remoteSettlement": true,  // 母币不在 BSC 上,结算方式不同
  "remoteTreasury": "0x4344a47Dca682443439eD8Ac70fD400975224e5b"
}

远端结算的社区不一样。 如果母币不在 BSC 上(比如 dontblink 的 BLINK 在 Robinhood Chain),金库不会去 PancakeSwap 买母币 —— 税以 BNB 分,烧的那一腿付给社区自己的钱包去转换销毁,每一笔都有链上记录。

错误码

出错时返回 { "code": "…", "error": "…" }。code 是承诺,error 不是 —— 拿 code 写你的重试逻辑;文案我们随时可能改得更好读。

建单时(你还没打钱)

codeHTTP意思怎么办
bad_envelope400发币字段平铺在顶层放进 request。最常见的一个
bad_address400地址不合法检查 creator / networkToken
missing_field400必填字段缺失error 里写了缺哪个
desc_too_long400描述超过 400 字截短
bad_presale400presaleQuoteBnb 不是正数—
bad_tax400税率不合法见税率规则
unknown_community400社区没入驻查 /communities
too_many_open_launches400挂着太多没打钱的单先打钱,或等它们过期
bad_status400这单的状态不允许这个操作比如重试一个已发成功的单
unauthorized401缺 key 或 key 不对—
not_found404没这一单—
rate_limited429撞限流看 Retry-After
internal500我们没预料到的情况可以重试;连续出就找我们
launcher_disabled503服务端没配发币密钥找我们,不是你的问题

上面这些全部在你打钱之前返回。 这是有意的。第一个真实用户的描述写了 612 字,而我们直到他打完 0.016 BNB 才告诉他超了 400 —— 那之后,所有能提前的检查都提前了。凡是建单时就能知道的错,都不该让人先付钱再发现。

发射时(钱已经打进来了)

出现在 GET /launch/:id 的 errorCode,回调体里也有同一个字段。

errorCode意思能重试怎么办
upstream_unavailable连不上 four.meme能我们已经在自动重试,最多 5 次
upstream_rejectedfour.meme 拒了参数不能改参数重新建单
underfunded落地钱包里钱不够能补足差额,自动继续
chain_reverted链上交易 revert不能看 error 原文
internal归不了类—找我们,把 id 给我们

归不了类的一律是 internal,不会硬套一个像是的码 —— 分类错的方向必须是「说不知道」,不是「说错原因」。把一单本该重试的归成 upstream_rejected,你就会放弃它。

幂等键

批量脚本一定会重试 —— 超时、502、网络抖。没有幂等键的重试每次都会开一个新钱包、给你一个新地址,而你以为是同一单。第一个真实用户就因此给两个地址各打了一次钱。

curl -X POST https://z500-api.nyxance.com/launch \
  -H 'idempotency-key: my-batch-2026-08-25-#7' \
  …

同一个键永远返回同一单,返回体里 "replayed": true。看到它就说明这不是新的一单,别再打一次钱。 键由你定,只要在你自己的范围内唯一 —— 批次号加序号最省事。

回调

request.callbackUrl 填一个公网 http(s) 地址,终态时我们 POST 给它。

{
  "id": 42,
  "status": "failed",
  "token": null,
  "error": "four.meme unreachable — connect ETIMEDOUT",
  "errorCode": "upstream_unavailable",
  "at": 1787645490000
}

回调失败我们不重试,也不会因此改变那一单的结果。地址必须是公网 —— 指向内网或 localhost 的会被拒。

税率与预设

四份税率必须正好加起来等于 100。填错在建单时就会被拒,不会等到花完钱。

参数index(默认)volume去向
buyFeeRate1000买入税 bps,0–1000
sellFeeRate200100卖出税 bps,下限 100,four.meme 不接受 0
rateFounder4010唯一会离开这枚币的一份 → z500 金库。下限 10
rateHolder4090用 BNB 付给它自己的持有人
rateBurn100烧它自己的供应
rateLiquidity100加它自己的池子

「税率 = 磨损」是错的算法

四份里只有 rateFounder 会离开这枚币。另外三份留在币内部:rateHolder 按持仓付给持有人、rateBurn 烧的是它自己的供应、rateLiquidity 进的是它自己的池子。所以握着大部分供应的人,税的大头会按持仓回到自己手上。

预设名义税(一个来回)真正流出刷 $100 的成本
volume1%1% × 10% = 0.1%约 $0.12
index3%3% × 40% = 1.2%约 $1.22

代价要说清楚: rateFounder 取下限意味着这枚币几乎不给 z500 金库供血,也就几乎不为它所在的社区买回和烧毁。volume 适合「我要交易量」,不适合「我要为这个社区做贡献」。两件事都合法,但不能同时要。

preset 定基线,再逐字段覆盖 —— 想要 volume 但买入税留 0.5%,加一个 "buyFeeRate": 50 就行,不用重写六个数字。

限流

写操作 每分钟 30 次、每天 600 次,按 key 计;读操作不限。超了返回 429 带 Retry-After。

这个额度是按「$2000 本金最多能发多少次」定的(最激进的合理配置约 580 次),正常用撞不到。它防的是脚本里一个写错的循环 —— 那种情况和正常批量发射在服务端长得一模一样。要跑更大的量提前说一声,改一个数字的事。

我们做不到的事

这部分不是承诺,是合约结构。你可以自己去 BscScan 上核。

税进金库之后谁都取不走

包括我们。它只有三条出路:烧掉、空投给持有人、按你部署时写死的比例付给你。金库合约里没有 withdraw 函数。

分成是单向棘轮

发完之后你只能把烧的比例调高、把自己的比例调低。这是合约层面的,不是承诺 —— 也正因为如此,买你币的人不需要相信你。

发币的真实成本是 gas

约 0.00026 BNB。presaleQuoteBnb 不是费用,它换成了你自己的币。平台不收创建费(createFee = 0)。

key 找我们要。丢了就说,我们换一把。

要批量到什么量级、需要更高额度、或者想把自己的社区接进来 —— 提前说一句,比撞上限再来问便宜得多。
